# Описание REST API endpoints

В ходе практической работы я реализовала REST API для управления студентами, преподавателями, учебными курсами и записями на курсы.

Для взаимодействия с данными используются HTTP-методы GET, POST, PUT и DELETE. Проверку запросов я выполняла через Swagger.

## 1. Students — Студенты

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/students` | Получение списка студентов |
| GET | `/api/students/{id}` | Получение студента по ID вместе с его курсами |
| POST | `/api/students` | Добавление нового студента |
| PUT | `/api/students/{id}` | Изменение данных студента |
| DELETE | `/api/students/{id}` | Удаление студента |

При создании студента передаются имя, фамилия, электронная почта и дата рождения.

Пример POST-запроса:

```json
{
  "firstName": "Alex",
  "lastName": "Smith",
  "email": "alex@example.com",
  "birthDate": "2004-05-15T00:00:00Z"
}
```

## 2. Teachers — Преподаватели

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/teachers` | Получение списка преподавателей |
| GET | `/api/teachers/{id}` | Получение преподавателя по ID |
| POST | `/api/teachers` | Добавление преподавателя |
| PUT | `/api/teachers/{id}` | Изменение данных преподавателя |
| DELETE | `/api/teachers/{id}` | Удаление преподавателя |

При создании преподавателя указываются имя, фамилия, электронная почта и кафедра.

Пример POST-запроса:

```json
{
  "firstName": "Anna",
  "lastName": "Ivanova",
  "email": "anna@example.com",
  "department": "Computer Science"
}
```

## 3. Courses — Учебные курсы

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/courses` | Получение списка курсов |
| GET | `/api/courses/{id}` | Получение курса по ID |
| POST | `/api/courses` | Создание нового курса |
| PUT | `/api/courses/{id}` | Изменение информации о курсе |
| DELETE | `/api/courses/{id}` | Удаление курса |

Для фильтрации списка курсов используются необязательные параметры `name` и `teacherId`.

Примеры запросов:

- `GET /api/courses?name=Web`
- `GET /api/courses?teacherId=1`

Пример POST-запроса:

```json
{
  "name": "Web Development",
  "description": "ASP.NET Core REST API Development",
  "credits": 5,
  "teacherId": 1
}
```

Значение `teacherId` должно соответствовать существующему преподавателю.

## 4. Enrollments — Записи студентов на курсы

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/enrollments` | Получение всех записей на курсы |
| GET | `/api/enrollments/{id}` | Получение записи по ID |
| POST | `/api/enrollments` | Запись студента на курс |
| PUT | `/api/enrollments/{id}` | Изменение оценки студента |
| DELETE | `/api/enrollments/{id}` | Удаление записи на курс |

Пример POST-запроса:

```json
{
  "studentId": 1,
  "courseId": 1
}
```

Пример PUT-запроса для изменения оценки:

```json
{
  "grade": 95
}
```

При записи студента на курс проверяется существование студента и курса. Повторная запись одного студента на один и тот же курс не допускается.

## 5. HTTP-коды ответов

В приложении предусмотрены следующие HTTP-статусы:

| Код | Описание |
|---|---|
| 200 OK | Запрос выполнен успешно |
| 201 Created | Объект успешно создан |
| 400 Bad Request | Некорректные входные данные |
| 404 Not Found | Запрашиваемый объект не найден |
| 409 Conflict | Нарушение бизнес-правил |
| 500 Internal Server Error | Внутренняя ошибка сервера |

## 6. Формат ответа API

Для возврата результатов я реализовала единый формат `ReturnResult<T>`.

Пример успешного ответа:

```json
{
  "statusCode": 200,
  "isSuccess": true,
  "result": {},
  "errorCode": null,
  "errorMessage": null,
  "traceId": "..."
}
```

В ответе передаются статус выполнения запроса, результат операции, информация об ошибке и идентификатор запроса.

## 7. Результат тестирования

Через Swagger я проверила создание и изменение студентов, добавление преподавателей, создание курсов, запись студентов на курсы, получение связанных данных, фильтрацию курсов и изменение оценок.

Реализованные endpoints обеспечивают основные операции управления университетскими курсами и взаимодействуют с базой данных PostgreSQL через Entity Framework Core.
